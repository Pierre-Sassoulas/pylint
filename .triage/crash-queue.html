The flag that hides half of them

Reaching for --disable=all --enable=F to cut the noise while hunting a crash hides three of the six. pylint skips a checker whose messages are all disabled, so the checker that was going to crash never runs and the file reads clean. Every verdict here comes from a default-configuration run:

python -m pylint --rcfile=/dev/null

"Does not reproduce" is not "fixed"

Most of these were never pylint-only bugs: they needed a particular release of xarray, panda3d, scipy, pymongo, black. Those libraries moved too, so a clean run says the pair is fine today, not that anything was repaired on purpose. Each row names the version it was tested against, so the next sweep can tell a real fix from a library that simply stopped provoking one.

Two of them swapped a crash for a false positive — the scipy and black imports now draw no-name-in-module on a C extension. That deserves its own issue rather than a quiet close.

What one machine cannot settle

Three reports need hardware or an interpreter this run does not have: a Windows console for the charmap encoding failure, Windows again for win32more, and Windows PyPy for the getset_descriptor one. The PyPy report was re-run on Linux PyPy and came back clean, which narrows it to Windows or to the astroid bump — but it does not close it.

A fourth, the pyreverse EmptyNode report, has no runnable trigger at all: the classes astroid rebuilds through a brain all walk cleanly, and the open fix constructs the node by hand to have something to test.
