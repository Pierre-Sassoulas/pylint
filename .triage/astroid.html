Two gaps with no astroid issue at all

Searched all 145 open issues; neither of these is filed, and both block a pylint issue that is currently labelled Needs PR with nowhere to send the PR.

  • _add_docstr returns Const(None). torch builds a large part of its API as qr = _add_docstr(_C._linalg.qr, "..."), and astroid infers every such assignment as None — so every one of those functions reads as not-callable. This is the whole of pylint #9218 and the closed duplicate #10710, and almost certainly of several other torch reports. One inference tip retires the family.
  • Inference truncation decides whether a false positive appears. pylint #4577 hinges on max_inferred: pd.read_csv(...) infers to [NoneType ×4, TextFileReader, Uninferable], never DataFrame, and whether the message fires depends on how deep inference happened to run for that pandas build. Raising the cap costs about 10× in runtime, so the real question — should unsubscriptable-object fire on a candidate list that contains Uninferable? — is a design decision nobody has written down.
